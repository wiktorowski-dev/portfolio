# Task: Transaction Data Processing and Aggregation System

## Context
Company Z processes large amounts of transaction data from various systems. We need a backend tool that enables:
- importing transaction data,
- validating it,
- simple processing,
- exposing aggregated results via API.

## Requirements

### 1. Data Import
- Implement an API endpoint: `POST /transactions/upload`, which accepts a CSV file with transaction data.
- **CSV Format:** 
  - `transaction_id` (UUID)
  - `timestamp` (ISO 8601)
  - `amount` (floating point number)
  - `currency` (e.g., PLN, EUR, USD)
  - `customer_id` (UUID)
  - `product_id` (UUID)
  - `quantity` (integer)
- The data should be validated (correct UUID format, date format, numeric types, non-empty required fields).
- Invalid rows should be logged/reported but should not block processing of valid rows.
- After validation, the data should be saved in a relational database — design an appropriate database schema.

### 2. Data Retrieval API
- `GET /transactions` — fetch a list of transactions with pagination and filtering options by `customer_id` and `product_id`.
- `GET /transactions/{transaction_id}` — fetch details of a single transaction.

### 3. Data Aggregation
- `GET /reports/customer-summary/{customer_id}` — summary for a customer:
  - total amount spent by the customer (in PLN; if transactions are in other currencies, assume fixed conversion rates, e.g., 1 EUR = 4.3 PLN, 1 USD = 4.0 PLN),
  - number of unique products purchased by the customer,
  - date of the customer's last transaction.
- `GET /reports/product-summary/{product_id}` — summary for a product:
  - total quantity sold of the product,
  - total revenue generated by the product (in PLN),
  - number of unique customers who bought this product.

### 4. Technologies
- Python 3.10+, FastAPI/Django, PostgreSQL or SQLite, SQLAlchemy/Django ORM, Pytest, Docker.

### 5. Bonus Points
- Asynchronous processing of CSV file import (e.g., using Celery or `async` mechanisms in FastAPI).
- Production-level error handling and logging.
- Simple API authentication mechanism (e.g., token in the header).
- Ability to generate reports for a given date range.
